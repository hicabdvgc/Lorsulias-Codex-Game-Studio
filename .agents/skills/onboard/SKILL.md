# Contributor Onboarding

Invoke `$onboard [role|area]`. Return orientation in conversation; do not write files.

Read `.codex/docs/workflow-catalog.yaml`, `.codex/docs/progression.md`, live
`docs/technical-preferences.md` and relevant current artifacts. The four section IDs are
conceptualization, development-schematics, pre-implementation, implementation. Report the declared
section separately from available outcomes and missing prerequisites. Preserve unknown/legacy stage
values until their interpretation is explicitly resolved; counts/existence cannot establish progress.
Story Status fields own progress; selected sprint YAML is derived. Active scope needs an explicit or
unique existing reference, never modification time. There is no review-mode file to create.

Read root AGENTS.md first. If absent/unreadable, report the missing instruction prerequisite and stop
without ONBOARDING COMPLETE. Read relevant directory instructions, actual architecture/framework,
resource/tool handoffs and selected responsibilities. Describe capabilities actually installed;
persona guidance grants no tool access or delegation authorization.

Cover project summary, role/area responsibility, actual roots/key documents, applicable standards,
current work, dependencies, pitfalls and candidate first activities. A reporting line, owner, active
sprint or milestone is named only when supplied or uniquely referenced. Preserve required independent
review and human evaluation. Read Git history when available; otherwise say recent activity unavailable
and use current artifacts. Do not infer another chat's live progress from local files.

Explain unknowns and the information needed to resolve them. ONBOARDING COMPLETE means useful
orientation was delivered; it does not certify the project or establish candidate task readiness.
