# Team Audio

Invoke `$team-audio [feature or area to design audio for]`. A target is required; missing target returns usage
without writes or delegation. Reject unknown control flags and ambiguous targets.

## Responsibility and evidence

Select only work needed by the request. Follow the current environment's delegation
policy. Available qualified people/agents can perform the responsibilities below;
roles do not require a fixed team. Identify self-review; preserve required independent
review and actual human evidence under `.codex/docs/review-workflow.md`.

Use existing bounded task authorization. Ask about consequential unresolved choices
or material scope expansion, without per-phase approval prompts. Before concurrent
work, assign one writer per output and keep shared sources read-only for other
executors. The current agent can write within its assigned scope. Re-read shared
records before saving and preserve concurrent changes and stable identities.

Read `.codex/docs/resource-preparation.md`; connect loose material and design outputs
to root RES_TYPE.md, relevant resource_templates/TYPE_TEMP definitions and res_lib/
when defined. Initial content design may record unresolved contracts. Prepared
resources and runtime integration require their actual contracts and evidence.
Use `.codex/docs/tool-development.md` only for a demonstrated unmet tooling need.

## Recovery and result

Read back every promised saved output before reporting delivery. Preserve completed
work if an executor fails. Assign the missing work to a qualified available executor
or mark the dependent activity BLOCKED; never invent the missing result. Report
selected scope, output paths, actual evaluation and remaining dependencies.
COMPLETE applies only to the requested deliverable when all its requirements are
met. A draft can be delivered as a draft; canon acceptance, implemented behavior,
produced media and human/play evaluation require their separate evidence.

## Context and output boundary

Resolve the feature/area by exact identity or explicit GDD references. Preserve its
display name and use a safe non-empty filename slug without path separators. Read
existing `design/audio/audio-[feature-slug].md` before updates. Read relevant GDD,
FRAMEWORK, docs/ACCESSIBILITY.md, live technical preferences, selected resource
mappings and `design/audio/sound-bible.md` when present. A missing sound bible can
be replaced by sufficient explicit sonic direction; record its provenance.

## Work sequence

1. **Audio direction** — establish the requested feature's sonic identity, emotional
   role, selected palette and applicable music/adaptive behavior. Audio-director
   expertise can support this. Budgets, priorities and buses remain selected choices.
2. **Sound/event design** — specify only the required sounds, trigger conditions,
   feedback behavior, selected parameters and source/resource requirements. A
   sound-designer can support this. A sound description does not deliver an audio file.
3. **Accessibility** — check the actual final cue inventory against the selected
   commitments, including alternatives for meaningful cues where required. Resolve
   conflicts between audio, visual/haptic feedback and UI timing. Missing required
   evaluation remains explicit; preserve useful partial work without claiming approval.
4. **Technical assessment, when needed** — technical-artist and the configured engine
   specialist can assess resource preparation, routing, selected budgets and import
   behavior. Verify engine/package claims for the actual selected versions; plugin
   documentation does not establish installation. Unconfigured choices prevent their
   dependent implementation, while a bounded design deliverable can remain useful.
5. **Production/integration only when requested** — identify the actual source,
   resource and code outputs covered by authorization. Use available qualified
   executors and tools. `gameplay-programmer` and `$dev-story` are installed. Implement
   only selected mechanisms; no automatic audio manager, middleware, adaptive music
   or engine migration is implied. Execute affected available checks and report
   unavailable runtime/listening/human evidence without a passing claim.

Save the requested audio design at `design/audio/audio-[feature-slug].md`. Update
sound-bible/resource outputs only when included in scope. Verify real delivered
media separately from specifications, prompts or event lists. Use `$asset-audit`
for applicable delivered-file checks. Report design, production and integration
results separately so design completion cannot imply successful audio playback.
