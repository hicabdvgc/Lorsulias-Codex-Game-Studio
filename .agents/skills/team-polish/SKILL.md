# Team Polish

Invoke as `$team-polish`. Arguments: `[feature or area to polish]`.

Read [.codex/docs/execution-and-evidence.md](../../../.codex/docs/execution-and-evidence.md) for authorization, status, criterion-level evidence, review and recovery contracts. Read the relevant sources before editing.


## Coordinate the bounded request

Resolve the described feature/area and existing design before authoring. Missing descriptions or
malformed control flags return usage. Read relevant GDD/FRAMEWORK, accepted architecture/CONTROL,
live preferences, accessibility and resource/tool contracts. Select necessary tasks and qualified
available executors; delegation requires current authorization, and role files grant no capability.
If delegated, give precise source/output paths, criteria and non-overlapping write ownership. Required
independent and human reviews remain required with any executor. Missing selected engine/root
information blocks dependent implementation, while supported independent work can proceed.

Ordinary story implementation uses `$story-readiness` then `$dev-story`; newly discovered work needs
bounded preparation. The pre-story vertical-slice route is confined to `$vertical-slice`'s authorized
scope. Carry existing task authorization and ask about consequential unresolved design changes.
Verify promised outputs at each handoff, preserve partial work and identify the dependent activity
blocked by a missing result. Re-read shared identities before writes. No automatic session lifecycle,
Git operation, story completion or phase advancement follows team work.

## Assess and refine

Identify actual implemented scope, relevant milestone goals, supplied budgets and observations.
Separate performance measurements, visual/audio direction, interaction feedback, accessibility and
stability issues. Unknown metrics or produced assets remain explicit. Select only needed work;
no automatic fixed parallel performance/visual/audio team applies.

Use `$perf-profile` for measured bottlenecks and propose proportionate changes. Use technical-art,
sound/audio and UI expertise for requested presentation refinements within selected resource contracts.
Audio instructions are not sound files; unobserved runtime behavior is not verified polish. An engine
programmer is relevant only for actual engine-level work and available capabilities.

Integrate selected corrections, run affected regressions/smoke checks and obtain required human
experience evidence. Preserve existing functionality; observed regressions block completion until
addressed or the requested scope is explicitly revised. Do not invent performance gains or universal
numeric budgets. Report actual changes, measurements, observation gaps and **COMPLETE / PARTIAL /
BLOCKED / NOT ASSESSED** for the polish scope. Release readiness requires its separate checklist and
gates, even when this refinement is complete.
