# Studio Skill and Persona Evaluation

This directory evaluates the studio's reusable skills and personas. Read
`catalog.yaml` for installed identities, categories, specification locations,
and recorded evaluation fields. Read `quality-rubric.md` for applicable outcome criteria.

Discover implementation/spec identities from actual files and compare sets;
numeric totals alone cannot prove coverage. A null spec is a declared pending
gap, not a successful test. Do not invent a path or omit an installed component from the audit.

Follow `$skill-test` for read-only static/spec/category/audit results. These modes
return results in conversation and never write result files or catalog dates.
A separate explicitly authorized evaluation task can save evidence and update
the relevant catalog fields; name that writer and distinguish executed scenarios
from examination of written instructions. Saved evaluations do not change these
read-only skill modes.

Specifications define representative requests, supplied inputs, expected useful
outcomes/formats, and meaningful assertions. A fixture description is not execution.
Investigate contradictions against the approved requirement before editing either
the procedure or its spec. Never weaken an assertion simply to obtain a pass.

Honor existing bounded authorization. Preserve unrelated work and apply the shared
skill-authoring and recovery guidance referenced by the root AGENTS.md.
