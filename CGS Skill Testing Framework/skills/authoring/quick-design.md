# Skill Test Spec: $quick-design

## Skill Summary

Exercise `.agents/skills/quick-design/SKILL.md` and its listed continuation with isolated fixtures.
Retain useful source interfaces while testing the adapted resource and evidence contracts.

## Static assertions

- Frontmatter name/description and UI metadata parse and match the installed identity.
- Retained references resolve or explicitly identify future/manual inputs.
- Output paths, modes and statuses agree with actual consumers and templates.
- Preserve bounded authorization, concurrent edits, required independent review and human evidence.

## Test cases

### Case 1: Permitted tuning

**Request / fixture:** FRAMEWORK permits an existing parameter change within 1–5; request changing 2 to 3.

**Expected outcome:** Save a tuning quick-spec with rationale, constraints, affected resource/integration work and verification; do not edit unrequested GDDs.

### Case 2: Contract change

**Request / fixture:** Request adding cross-system stock reservation where the framework requires full system design.

**Expected outcome:** REDIRECTED to $design-system; no four-hour or one-week threshold and no review waiver.

### Case 3: Existing output

**Request / fixture:** Update one section of an existing quick-spec; FRAMEWORK criteria are absent in a second fixture.

**Expected outcome:** Preserve other sections; clarify missing criteria before declaring quick scope.

## Evidence and grading

Record raw fixture inputs, request, actual response/artifacts, method and observed
result. Static reading, guided current-agent exercises, script execution and native
runtime dispatch are separate evidence. A fixture or expected answer alone is not
execution. Inspect useful output and failed prerequisites; rerun affected cases after
correction. Apply the shared rubric without arbitrary section or step counts.
