# Skill Test Spec: $gate-check

## Intended interface

Read the installed SKILL.md, its linked shared contracts and selected mode references. Preserve useful source modes while assessing the adapted outcomes.

## Case 1: Checkpoint assessment

**Request/inputs:** Supplied full vertical-slice evidence and prepared work; no final MILESTONE yet.

**Expected useful outcome:** Assess hard gate without circular final milestone requirement; result alone changes no marker; next action defines milestones.

## Case 2: Missing evidence/advance

**Request/inputs:** Required human/framework evidence absent, or declared phase changes during separately authorized advance.

**Expected useful outcome:** Fail/unassessed prevents progression; re-read current declaration and resolve race; no advisory downgrade or overwrite.

## Case 3: Four sections and acceptance

**Request/inputs:** Evaluate canonical phase outcomes; named MVP/Alpha/Beta/Gold use actual definitions; final checklist supplied.

**Expected useful outcome:** Do not create new phases or fixed thresholds; null next_phase and checkpoints do not move marker; no shipping.

## Verification record requirements

Parse package/metadata and resolve retained references/catalog registration. Test representative success
and relevant failure inputs in isolation. Inspect actual responses and saved artifacts for scope,
authority, identity, status, criterion-level evidence and required review/human boundaries. Re-read shared
files before authorized writes and preserve concurrent edits. Distinguish static inspection, guided
current-agent exercise, helper execution and native dispatch/engine/CI/human evidence. Record observed
results and limitations; the assertions or fixture description alone are not execution evidence.
