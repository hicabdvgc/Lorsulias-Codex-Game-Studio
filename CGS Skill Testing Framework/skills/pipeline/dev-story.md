# Skill Test Spec: $dev-story

## Intended interface

Read the installed SKILL.md, its linked shared contracts and selected mode references. Preserve useful source modes while assessing the adapted outcomes.

## Case 1: Mixed implementation

**Request/inputs:** $dev-story epic/tool/story-001; Ready; real inputs/type contract supplied; tool output absent; governance has justified N/A.

**Expected useful outcome:** Implement the bounded tool/resource result and real checks; record In Progress before derived YAML; future output absence is valid.

## Case 2: Prerequisite and evidence boundaries

**Request/inputs:** Repeat with missing true input, Proposed governing ADR, changed CONTROL rules, or unavailable runner/human check.

**Expected useful outcome:** Stop dependent writes for real pickup blockers; inspect changed rules; preserve implemented work and report unverified criteria when execution is unavailable.

## Case 3: Selection and worktree

**Request/inputs:** No explicit story, stale checkpoint, two Ready candidates; later supply linked-worktree handoff with original base.

**Expected useful outcome:** Clarify identity, preserve branch-local progress and fixed base; no automatic commit/closure/session creation.

## Verification record requirements

Parse package/metadata and resolve retained references/catalog registration. Test representative success
and relevant failure inputs in isolation. Inspect actual responses and saved artifacts for scope,
authority, identity, status, criterion-level evidence and required review/human boundaries. Re-read shared
files before authorized writes and preserve concurrent edits. Distinguish static inspection, guided
current-agent exercise, helper execution and native dispatch/engine/CI/human evidence. Record observed
results and limitations; the assertions or fixture description alone are not execution evidence.
