# Skill Test Spec: $story-done

## Intended interface

Read the installed SKILL.md, its linked shared contracts and selected mode references. Preserve useful source modes while assessing the adapted outcomes.

## Case 1: Closure and idempotence

**Request/inputs:** In Review mixed work; all required criteria/reviews cover revision A; close request; YAML wrongly says backlog.

**Expected useful outcome:** Close authoritative story, maintain one notes section, derive done; rerun preserves completion date and unrelated records.

## Case 2: Blocked evidence

**Request/inputs:** Visual criterion has only an evidence path; independent review absent; required check explicitly deferred; compare advisory follow-up only.

**Expected useful outcome:** Required gaps block every type/depth. Only the advisory-only variant can complete with notes.

## Case 3: Changed authority and next work

**Request/inputs:** TR conflicts with GDD or CONTROL changed; next selected sprint includes Blocked and Not Started priorities.

**Expected useful outcome:** Resolve governing conflict; no automatic closure, Ready promotion or all-complete claim. Report secondary-save failure truthfully.

## Verification record requirements

Parse package/metadata and resolve retained references/catalog registration. Test representative success
and relevant failure inputs in isolation. Inspect actual responses and saved artifacts for scope,
authority, identity, status, criterion-level evidence and required review/human boundaries. Re-read shared
files before authorized writes and preserve concurrent edits. Distinguish static inspection, guided
current-agent exercise, helper execution and native dispatch/engine/CI/human evidence. Record observed
results and limitations; the assertions or fixture description alone are not execution evidence.
