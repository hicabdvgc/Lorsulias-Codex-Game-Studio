# Skill Test Spec: $team-audio

## Skill Summary

Exercise `.agents/skills/team-audio/SKILL.md` and its listed continuation with isolated fixtures.
Retain useful source interfaces while testing the adapted resource and evidence contracts.

## Static assertions

- Frontmatter name/description and UI metadata parse and match the installed identity.
- Retained references resolve or explicitly identify future/manual inputs.
- Output paths, modes and statuses agree with actual consumers and templates.
- Preserve bounded authorization, concurrent edits, required independent review and human evidence.

## Test cases

### Case 1: Design only

**Request / fixture:** Specify a puzzle-success cue with supplied sonic brief, no sound bible and no engine selected.

**Expected outcome:** Save design/audio/audio-[slug].md as scoped design; identify media and runtime work pending without spawning absent implementation roles.

### Case 2: Cue conflict

**Request / fixture:** Selected commitment requires a visible completion cue but audio event specifies sound alone.

**Expected outcome:** Identify the exact unmet requirement, preserve useful draft work and block affected acceptance until resolved and evaluated.

### Case 3: Implementation and recovery

**Request / fixture:** Request real playback with no engine/runtime, or promised audio file is missing.

**Expected outcome:** Do not infer implementation from spec; name missing dependency and preserve completed design; no fabricated playback or media.

## Evidence and grading

Record raw fixture inputs, request, actual response/artifacts, method and observed
result. Static reading, guided current-agent exercises, script execution and native
runtime dispatch are separate evidence. A fixture or expected answer alone is not
execution. Inspect useful output and failed prerequisites; rerun affected cases after
correction. Apply the shared rubric without arbitrary section or step counts.
