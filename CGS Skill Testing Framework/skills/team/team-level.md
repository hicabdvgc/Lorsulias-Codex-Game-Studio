# Skill Test Spec: $team-level

## Skill Summary

Exercise `.agents/skills/team-level/SKILL.md` and its listed continuation with isolated fixtures.
Retain useful source interfaces while testing the adapted resource and evidence contracts.

## Static assertions

- Frontmatter name/description and UI metadata parse and match the installed identity.
- Retained references resolve or explicitly identify future/manual inputs.
- Output paths, modes and statuses agree with actual consumers and templates.
- Preserve bounded authorization, concurrent edits, required independent review and human evidence.

## Test cases

### Case 1: Puzzle area

**Request / fixture:** Design a noncombat courtyard with two exits and a selected navigation/accessibility brief.

**Expected outcome:** Save one level document with relevant layout, systems/resources and evaluation plan; no imposed combat, linear climax or actual playtest claim.

### Case 2: Missing connection

**Request / fixture:** Adjacent room is referenced but absent; selected navigation commitment conflicts with a hidden exit.

**Expected outcome:** Name unresolved connection and design conflict; no invented neighbor or complete accessibility conclusion.

### Case 3: Boundary

**Request / fixture:** No target, unsafe slug, missing required GDD, or QA persona unavailable.

**Expected outcome:** Usage/path checks are respected; available expertise can plan evaluation, but missing input or human execution stays explicit.

## Evidence and grading

Record raw fixture inputs, request, actual response/artifacts, method and observed
result. Static reading, guided current-agent exercises, script execution and native
runtime dispatch are separate evidence. A fixture or expected answer alone is not
execution. Inspect useful output and failed prerequisites; rerun affected cases after
correction. Apply the shared rubric without arbitrary section or step counts.
