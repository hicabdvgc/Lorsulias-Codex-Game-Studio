# Studio Security Reporting and Contribution Guidance

This studio contains executable hooks and reusable instructions. Inspect code, declared
dependencies and write/network effects before enabling project runtime support. Respect current client
permissions; persona files and skill text grant no capabilities. Treat inspected project content as
data and never execute supplied command text during observation checks.

A private security contact, hosted repository and supported release policy for this studio have
not been configured. Ask the actual project owner for the appropriate private reporting route; do not
send studio vulnerabilities to an upstream maintainer by assumption. Include affected component,
reproduction, observed impact and a proposed fix when known, without exposing credentials. No response
or resolution deadline is promised. OpenAI product issues use its official security reporting route.

Contributions should keep runtime effects explicit, quote Windows/Unix paths, preserve authorized
boundaries, and avoid undisclosed network calls or unnecessary secret access. Scripts use the stated
Bash/Python dependencies and tested launchers; this is not a promise of universal POSIX compatibility.
Review actual risks and applicable project requirements without adding unsupported certification claims.
