# Upgrading the Adapted Studio

Preserve a recoverable copy of local work and inspect the incoming diff. Merge reviewed changes to
instructions, skills, personas, templates, hooks and specifications with their consumers. Preserve
live technical preferences, designs, resources/tools, accepted decisions, registries, work status,
release evidence and session notes. Do not replace these with upstream defaults.

Source distributions are reference material. The attribution links in NOTICE.md are not configured
update remotes or support promises for this studio. For an actual Git project use its selected
reviewed merge/cherry-pick process; non-Git projects use a reviewed file merge. Never reset user work
or automatically install dependencies/engines to upgrade the studio.

Inspect configuration changes separately and retain selected model, reasoning, permissions and
concurrency. Recheck package metadata, references, changed helper behavior and applicable native
loading. A successful direct script check does not prove live hook dispatch. Existing legacy session
notes and patch-note copies remain preserved until explicitly migrated using current interfaces.

Preserve live project preferences and conversational review decisions when integrating
upstream changes. Follow the current [review workflow](<.codex/docs/review-workflow.md>)
and [settings guidance](<.codex/docs/settings-local-template.md>).
Use the reusable checks documented in [runtime checks](<CGS Skill Testing Framework/runtime/README.md>)
for affected regressions. Game validation and native runtime qualification require their own evidence.
