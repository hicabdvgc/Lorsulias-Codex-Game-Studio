# Design Directory

Use developer-authored `gdd/CONCEPT.md`, preliminary/full `gdd/BREAKDOWN.md`, and
identifiable system GDDs. Read the applicable templates and framework maturity.
Initial system design uses full BREAKDOWN and preliminary FRAMEWORK; record future
resource schema questions instead of requiring their output before design begins.

Describe behavior, interactions, rules and relevant evidence clearly. Numerical
rules need units, ranges and examples; experiential goals need human evaluation
methods. Include other sections when they serve the system's intended reader.
Trace shared facts to the owning design and registry; update affected references
within the authorized task. Review scope and independence follow shared guidance.

UX, resource audits, and cross-GDD review skills are installed. Initial GDDs can record resource needs before schemas exist; later integration requires the applicable root RES_TYPE.md and resource_templates/ contracts. Read `.codex/docs/resource-preparation.md` for the res_lib/ handoff. No universal genre, priority tier,
document section count, or architecture layer is imposed here.
