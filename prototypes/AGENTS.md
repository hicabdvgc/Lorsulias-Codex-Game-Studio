# Prototype Work

Choose a bounded hypothesis, suitable HTML/engine/paper route, and evidence that
can answer it. Read the `$prototype` skill and report template when applicable.
Keep experiment outputs in the declared prototype workspace and preserve unrelated
project files. Any additional write targets require task authorization.

Shortcuts can be appropriate when they do not invalidate the experiment. Record
them, actual run instructions, dependencies, observations and remaining uncertainty
in the prototype report. A simulated paper walkthrough is distinct from human play.

Decide retention explicitly. Reuse needs review against production contracts;
successful experiments do not imply production readiness or require automatic
deletion. `$vertical-slice` has its separate hard gate.
